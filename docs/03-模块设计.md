## 2. 接口契约

### 2.1 `src/models/schemas.py`（字段级变更）

**新增类型**

```python
class FunctionCall(BaseModel):
    name: str
    arguments: str          # JSON 字符串（OpenAI 规范要求是字符串，不是对象）

class ToolCall(BaseModel):
    id: str                 # 由 relay 生成：f"call_{uuid4().hex[:8]}"
    type: Literal["function"] = "function"
    function: FunctionCall

class FunctionDef(BaseModel):
    name: str
    description: Optional[str] = None
    parameters: Optional[Dict[str, Any]] = None

class ToolDef(BaseModel):
    type: Literal["function"] = "function"
    function: FunctionDef

class FunctionCallDelta(BaseModel):
    name: Optional[str] = None
    arguments: Optional[str] = None

class ToolCallDelta(BaseModel):
    index: int = 0
    id: Optional[str] = None
    type: Optional[Literal["function"]] = None
    function: Optional[FunctionCallDelta] = None
```

**扩字段（全部可选、向后兼容）**

| 类型 | 新增字段 | 说明 |
|---|---|---|
| `ChatMessage` | `role` 的 `Literal` 追加 `"tool"` | 否则 agent 回传工具结果会被 422 |
| `ChatMessage` | `content: Optional[str] = None` | 由 `str` 放宽；assistant 带 `tool_calls` 时 `content` 可为 `null` |
| `ChatMessage` | `tool_calls: Optional[List[ToolCall]] = None` | assistant 发起的调用 |
| `ChatMessage` | `tool_call_id: Optional[str] = None` | `role:"tool"` 必填（R4） |
| `ChatCompletionRequest` | `tools: Optional[List[ToolDef]] = None` | 缺省 `None` → 走原路径（R1） |
| `ChatCompletionRequest` | `tool_choice: Optional[Union[str, Dict[str, Any]]] = None` | `"none"`/`"auto"`/`"required"`/`{"type":"function",...}` |
| `DeltaMessage` | `tool_calls: Optional[List[ToolCallDelta]] = None` | 流式工具调用分片 |

**契约不变量**

- **C1**：`content` 放宽不得改变既有响应形态 → 见 §5「I1 落地」。
- **C2**：不传 `tools` 且存在 `content is None` 的消息 → **400**（显式拦截，避免语义缝隙）：
  ```python
  if not request.tools and any(m.content is None for m in request.messages):
      raise HTTPException(status_code=400, detail="content is required when tools are not provided")
  ```
- **C3**：`role:"tool"` 且缺 `tool_call_id` → 400（R4）。

### 2.2 `src/tools/spec.py`

```python
TOOL_CALL_OPEN = "<tool_call>"
TOOL_CALL_CLOSE = "</tool_call>"

class ParseState(Enum):
```

### 2.3 `src/tools/render.py`

```python
def build_system_prompt(tools: List[dict], tool_choice) -> str
def render_messages(messages: List[ChatMessage], tools: List[dict], tool_choice) -> List[ChatMessage]
```

**`build_system_prompt` 输出契约**（模板固定，便于回归）：

```
你是一个可以使用外部工具的助手。

可用工具（JSON Schema）：
<tools>
{"name": "...", "description": "...", "parameters": {...}}
...
</tools>

调用规则：
1. 需要工具时，只输出工具调用，不要输出任何其他文字：
   <tool_call>{"name": "工具名", "arguments": {"参数": "值"}}</tool_call>
2. 一轮需要多个工具时，连续输出多个 <tool_call>...</tool_call> 块。
3. 不需要工具时，直接用自然语言回答，不要输出 <tool_call>。
4. arguments 必须是合法 JSON 对象，且符合该工具的 parameters Schema。
```

`tool_choice` 语义：

| 值 | 渲染行为 | 解析行为 |
|---|---|---|
| `None` / `"auto"` | 标准注入 | 正常解析 |
| `"none"` | **不注入工具规范**，不输出调用规则 | **跳过解析**（纯文本直通） |
| `"required"` | 标准注入 + 追加 `FORCE_ANY_HINT` | 正常解析 |
| `{"type":"function","function":{"name":X}}` | 只注入 `X` 一个工具 + 追加 `FORCE_ONE_HINT(X)` | 正常解析 |

**`render_messages` 契约**：

- 取出全部 `system` 消息文本，拼进 system 段落（若无 system 则用默认身份句）。
- 其余消息按序压平成**一条** `ChatMessage(role="user")`，标签化：
  - `user` → `<user>…</user>`
  - `assistant`（纯文本）→ `<assistant>…</assistant>`
  - `assistant`（有 `tool_calls`）→ `<assistant_call name=".." call_id="..">{"参数"..}</assistant_call>`
  - `tool` → `<tool_result call_id="..">…</tool_result>`
- 末尾追加 `<current_user_message>…</current_user_message>`（最后一条 user 的内容）。
- `content is None` 一律归一化为 `""`（**不得让 None 漏到 provider**）。
- **返回值长度恒为 1**（这是"上游只认最后一条 user"约束下的硬要求，需断言）。

### 2.4 `src/tools/parse.py`

```python
class ToolCallStreamParser:
    def __init__(self) -> None
    def feed(self, chunk: str) -> List[Event]     # 无返回时才可安全丢弃
    def finish(self) -> List[Event]               # 生成结束后收尾
    def has_tool_calls(self) -> bool

def extract(text: str) -> tuple[str, list[dict]]   # 非流式：一次性解析
def to_tool_calls(raw: list[dict]) -> List[ToolCall]  # 补 id/type，封装 arguments 为 JSON 字符串
```

**支持格式（按优先级）**

| # | 形态 | 触发 |
|---|---|---|
| F1 | `<tool_call>{json}</tool_call>` | 主格式 |
| F2 | ```` ```json {json} ``` ```` 围栏 | 模型用围栏包裹时 |
| F3 | 裸 JSON 对象且含 `name` + (`arguments` \| `parameters`) | 兜底 |
| F4 | XML：`<tool_call><invoke name=".."><parameter name=".." string="true">值</parameter></invoke></tool_call>` | 工具集较大（13 件实测）时模型退回自带类型标注的 XML |
| F5 | DSML 标记：`<tool｜｜DSML｜｜ calls>`（竖线为全角 U+FF5C 或 ASCII，元素名与属性同 F4） | 上游内置工具协议的原始标记；先经 `_normalize_dsml` 归一成标准标签再走 F4 |

> F4/F5 于 2026-09-11 由真机复现驱动新增：13 工具链 + 长 system prompt 下，
> deepseek-flash 稳定输出 F5（且标签会被上游切片到只剩 `‖DSML‖` 碎片），
> 归一化器必须扣留「尖括号开头但尚未收齐右尖括号」的尾巴，否则 `</` 会先漏成正文。

**流式状态机**

```
        ┌──────────────────────── NORMAL ────────────────────────┐
        │  fast-path 嗅探：首个非空白字符 ∉ {'<', '`'} → 直通模式   │
        │  直通模式：每 chunk 立即产出 CONTENT（零额外延迟）        │
        │  缓冲模式：未见 TOOL_CALL_OPEN 前不产出，暂存 buffer      │
        └───────────────┬─────────────────────────▲──────────────┘
                        │ 命中 TOOL_CALL_OPEN      │ 未命中且已确认是普通文本
                        ▼                          │ → 把 buffer 作为 CONTENT 吐出
                 ┌── IN_TOOL_CALL ──┐              │ → 切回直通模式
                 │  累积 buffer      │──────────────┘
                 │  不产出 CONTENT   │
                 └───────┬──────────┘
                         │ 命中 TOOL_CALL_CLOSE
                         ▼
                 解析 JSON → 产出 TOOL_CALL 事件 → 回到 NORMAL（缓冲模式）
```

**降级规则（R2，必须可断言的失败路径）**

| 情形 | 行为 |
|---|---|
| `IN_TOOL_CALL` 中 JSON 解析失败 | 整个块按 **CONTENT 原文**吐出（不抛异常） |
| `finish()` 时仍在 `IN_TOOL_CALL`（缺闭合标签） | 先尝试直接解析 buffer；失败则按 CONTENT 吐出 |
| `tool_choice == "none"` | 完全不解析 |
| 任何内部异常 | 捕获 → 兜底为 `content=原文`、`tool_calls=[]`，**绝不 5xx**（I2） |
| 生成中途连接断开 | `pipeline` 的 `finally` 负责清空 parser 的 buffer（生成级状态回收） |

**`extract` 返回约定**：`(content, raw_calls)`；`content` 已剥离全部工具调用块。

### 2.5 `src/tools/pipeline.py`

```python
@dataclass
class Prepared:
    request: ChatCompletionRequest      # 替换 messages 为压平后的单条
    tools: List[dict]
    tool_choice: Any
    system_prompt: str

def prepare(request: ChatCompletionRequest) -> Prepared
def build_response(prepared: Prepared, upstream_text: str) -> ChatCompletionResponse
async def stream(prepared: Prepared, provider, request) -> AsyncGenerator[str, None]
```

**`build_response` 契约**

- `content`：解析出的正文；若存在工具调用且正文为空 → `content=None`（OpenAI 规范允许）。
- `tool_calls`：`to_tool_calls(raw)` 结果；无则 `None`。
- `finish_reason`：有工具调用 → `"tool_calls"`；否则 `"stop"`。
- `usage`：沿用现状（全 0），本次不改。

**`stream` 契约（SSE 分片规范）**

| 时机 | 产出 |
|---|---|
| 首个事件前 | `delta={"role":"assistant"}` |
| 每个 CONTENT 事件 | `delta={"content": 文本}` |
| 每个 TOOL_CALL 事件 | 单个 delta 携带完整调用：<br>`delta={"tool_calls":[{"index":i,"id":"call_x","type":"function","function":{"name":名,"arguments":"{...}"}}]}` |
| 结束 | 终止 chunk：`finish_reason = "tool_calls"` 或 `"stop"` |
| 之后 | `data: [DONE]`（既有行为） |

> 一次性给出 `arguments` 全量等价于"单分片"，符合 OpenAI 增量拼接语义。
> 每个 `index` 的**首个** delta 必须带 `id` + `function.name`。

**执行流形态**：`prepare → provider.chat_completion_stream → parse.feed → yield SSE`，
是**顺序管道**；唯一的状态机在 `parse` 内（见 §2.4）。

## 3. `src/api.py` 接线（最小 diff）

```python
@app.post("/v1/chat/completions")
async def chat_completions(request, authorization=None):
    # R1 / C2：无 tools 时完全走原路径（既有代码一行不动）
    if not request.tools:
        if any(m.content is None for m in request.messages):
            raise HTTPException(status_code=400, detail="content is required when tools are not provided")
        ... 既有实现原样 ...

    # --- 工具调用路径（新增，约 25 行）---
    if any(m.role == "tool" and not m.tool_call_id for m in request.messages):
        raise HTTPException(status_code=400, detail="tool_call_id is required for role=tool")

    provider_name, provider = get_provider_for_model(request.model)
    prepared = pipeline.prepare(request)

    if request.stream:
        return StreamingResponse(pipeline.stream(prepared, provider, request), media_type="text/event-stream", headers=...)
    upstream = await provider.chat_completion(prepared.request)
    text = upstream.choices[0].message.content or ""
    return pipeline.build_response(prepared, text)
```

**为什么把非 tools 分支写成前置 if**：这是 I1（逐字段等价）的**结构性保证**——
旧代码物理上没有被执行路径触碰过，而不是"改完再测出来没坏"。

## 4. 错误码与降级矩阵

| 场景 | HTTP | 行为 |
|---|---|---|
| `tools` 为 `null` | — | 走原路径（无行为变化） |
| 非 tools 且 `content is None` | 400 | 显式拦截（C2） |
| `role:"tool"` 缺 `tool_call_id` | 400 | 显式拦截（R4） |
| `tools` 为空数组 `[]` | — | 视为无工具 → 走原路径（与 `null` 等价） |
| 模型未输出工具调用 | 200 | `finish_reason="stop"`，纯 `content`（正常情况，非错误） |
| 工具调用 JSON 畸形 | 200 | 降级为 `content`，不报错（R2 / I2） |
| 上游 401/500 | 500 | 既有行为（`RuntimeError` → `HTTPException(500)`），本次不改 |
| 上游超时 | 500 | 既有行为 |

## 5. I1「逐字段等价」的落地方式（关键）

| 路径 | 现状序列化 | 新增 `None` 字段是否泄漏 | 处置 |
|---|---|---|---|
| **流式** | `chunk.model_dump_json(exclude_unset=True, exclude_none=True)` | ❌ 不泄漏（`exclude_none=True` 已排除） | **无需改动** |
| **非流式** | `return response` → FastAPI 默认序列化（**包含** `None`，故现有响应里已有 `"name": null`） | ✅ 会泄漏 `tool_calls: null`、`tool_call_id: null` | 非 tools 分支返回前**仅剥离本次新增的两个键** |

```python
        # 非 tools 路径：剥离本次新增字段，保持响应与改造前逐字段等价（I1）
        payload = response.model_dump()
        message = payload["choices"][0]["message"]
        message.pop("tool_calls", None)
        message.pop("tool_call_id", None)
        return JSONResponse(payload)
```

**回归判定（精确口径）**：P3 基线快照（改造前录制）与改造后响应做 diff，**要求 diff == 0**。

⚠️ 但 diff 必须**先归一化生成性字段**：模型每次生成的 `content` 文本天然不同，
若直接比文本值必然失败。因此比对前把 `choices[].message.content`、`choices[].delta.content`
替换为占位符 `"<TEXT>"`，**只比较字段集合、类型骨架与非生成性字段值**
（`id`/`created`/`model`/`object`/`finish_reason`/`usage` 等同样属易变字段，一并占位）。

> 由 `capture_baseline.py --compare` 实现该归一化比对。

若未来想把 `exclude_none` 统一收紧（会让 `"name": null` 一并消失），
那属于**独立的、需显式决策的兼容性变更**，不夹带在本次改动里。

## 6. 执行流模式总览

| 场景 | 形态 | 说明 |
|---|---|---|
| 非 tools 请求 | **顺序管道** | 与改造前完全一致 |
| tools + 非流式 | 顺序管道 | `prepare → 上游(整包) → extract → build_response` |
| tools + 流式 | 顺序管道 + **局部状态机** | 状态机仅存在于 `ToolCallStreamParser`，生命周期 = 单次生成 |
| 并发 | 无 | 不新增线程/任务；同一请求内串行 |
